# 💥 BLEVE Pressure Prediction

A machine learning project for predicting the **peak pressure generated by Boiling Liquid Expanding Vapour Explosions (BLEVEs)** using physical simulation data.

The project explores data preprocessing, physics-informed feature engineering, target transformation, multiple machine learning algorithms, hyperparameter tuning, and weighted ensemble learning to predict BLEVE pressure. The final solution combines **XGBoost, LightGBM, Random Forest, and Ridge Regression**.

## 📊 Results

**Final Kaggle Private Leaderboard MAPE: `0.24181`**

The individual models achieved the following validation performance:

| Model            | Validation MAPE | Validation R² |
| ---------------- | --------------: | ------------: |
| XGBoost          |           0.136 |         0.924 |
| LightGBM         |           0.138 |         0.921 |
| Random Forest    |           0.184 |         0.882 |
| Ridge Regression |           0.986 |         0.520 |

The final predictions were generated using a weighted ensemble, with the strongest weights assigned to XGBoost and LightGBM, while Random Forest and Ridge Regression provided additional model diversity.

## 🔬 Project Overview

BLEVE events involve complex nonlinear interactions between physical variables such as:

* Pressure
* Temperature
* Tank geometry
* Vapour-liquid ratios
* Sensor position
* Obstacle placement

The objective was to develop a machine learning pipeline capable of learning these relationships from physical simulation data and predicting the resulting target pressure.

## 🧹 Data Preprocessing

The original training dataset contained **10,050 rows and 25 columns**, including the target variable. After removing records with missing target values, 10,040 training samples remained.

The preprocessing pipeline included:

* Median imputation for missing numerical values
* Mode imputation for missing categorical values
* Standardization of inconsistent categorical values
* Duplicate-record checking
* Target Winsorization at the 1st and 99th percentiles
* Log transformation using `log(1 + y)`
* Inverse transformation of predictions using `exp(y) - 1`

The target transformation was particularly useful for reducing the influence of extreme pressure values and improving model stability.

## ⚙️ Feature Engineering

Physics-informed features were engineered to better represent the physical relationships involved in BLEVE events.

Examples include:

| Feature                   | Purpose                                                  |
| ------------------------- | -------------------------------------------------------- |
| `Tank_Volume`             | Represents tank capacity and stored energy               |
| `Vapour_Vol_Ratio`        | Represents the proportion of the tank occupied by vapour |
| `Inv_Dist`                | Models pressure decay with obstacle distance             |
| `Sensor_XY_Dist`          | Represents horizontal sensor-obstacle distance           |
| `Temp_Diff`               | Captures thermal differences between vapour and liquid   |
| `Crit_Pressure_Ratio`     | Represents relative pressure severity                    |
| `Pressure_Volume`         | Provides a proxy for released energy                     |
| `Temp_Diff_sq`            | Captures nonlinear thermal effects                       |
| `Dist_Height_Interaction` | Represents obstacle-blast interactions                   |
| `Sensor_z_rel`            | Represents relative sensor elevation                     |

A small epsilon value was added to denominators in ratio-based features to avoid division-by-zero errors.

## 🤖 Machine Learning Models

Four models were selected for the final solution.

### XGBoost

XGBoost was selected for its ability to model complex nonlinear relationships in structured tabular data while incorporating regularization to help reduce overfitting.

### LightGBM

LightGBM provided a faster gradient-boosting approach using histogram-based learning and leaf-wise tree growth. Its different learning behaviour also provided useful diversity within the final ensemble.

### Random Forest

Random Forest was included as a bagging-based model to reduce variance and provide prediction behaviour different from the boosting models.

### Ridge Regression

Ridge Regression provided a fundamentally different linear model. Although its standalone performance was substantially weaker, its different prediction patterns allowed it to contribute additional diversity to the ensemble.

## 🔧 Hyperparameter Tuning

Hyperparameter tuning was performed using **Google Colab CPU runtimes**.

To keep computational requirements manageable, tuning was performed using a 5,000-sample subset with limited cross-validation and randomized search iterations.

A **GroupKFold** validation strategy was used to ensure that data belonging to the same `Sensor ID` did not appear in both training and validation folds. This reduced the risk of data leakage and produced a more realistic evaluation.

### Selected Configurations

**XGBoost**

```text
n_estimators: 700
max_depth: 8
learning_rate: 0.05
subsample: 0.8
colsample_bytree: 0.8
reg_alpha: 0.01
reg_lambda: 1.5
```

**Random Forest**

```text
n_estimators: 300
max_depth: 20
min_samples_split: 5
```

**Ridge Regression**

```text
alpha: 10
```

LightGBM was tuned using a similar randomized-search approach with unrestricted tree depth (`max_depth = -1`).

## 🧠 Ensemble Learning

The final solution combined the four models using a **weighted ensemble**.

The ensemble weights were initially assigned based on validation MAPE and subsequently refined through a grid search:

```text
XGBoost          0.42
LightGBM         0.41
Random Forest    0.15
Ridge Regression 0.02
```

This approach allowed the final model to benefit not only from the strongest individual models but also from the differing prediction patterns of the ensemble members.

## ⚠️ Challenges

### Computational Constraints

One of the major challenges was balancing model performance with the computational limitations of Google Colab CPU runtimes. Full hyperparameter searches and cross-validation configurations could require several hours.

To manage this, the tuning dataset was reduced to 5,000 samples, the number of folds was limited, and randomized search iterations were reduced.

### Unstable Engineered Features

Some ratio-based engineered features produced extremely large or infinite values when denominators became very small.

This was addressed by introducing a small epsilon value into denominators and handling remaining missing or invalid values through median imputation.

### Ensemble Diversity

An interesting finding was that Ridge Regression performed considerably worse than the tree-based models individually. However, its different prediction behaviour still allowed it to contribute to the ensemble.

This demonstrated the value of **model diversity**, rather than selecting models solely based on standalone performance.
